# Dokumente

Paper and files into Paperless, for the household on a Laib box
(laib ADR 0028): a stack from the scanner or the inbox folder is turned,
read, split into its documents by the household model and filed; contracts
and invoices get their fields read and their notice and due dates reminded.

- `scan/` — the stack: the scanner (SANE, network or USB), the inbox folder,
  separator sheets, blank pages, the split, filing into Paperless' consume
  folder, the status file. Carried from laib's `scan/` with its history
  (frozen at laib 8236b19).
- `vertraege/` — contracts and invoices: their fields from the text, notice
  and due reminders. Carried from laib's `templates/paperless/` with its
  history.

Laib runs it (its template passes the scanner, the folders, the model
through the lease, the secrets); Haus and the Bote are its faces. The image
is `ghcr.io/mdopp/dokumente`, built on every push to main.

Tests run in the image: `docker build -t dokumente:test -f Containerfile .`
then `docker run --rm -v "$PWD:/src:ro" -w /src --entrypoint python3
dokumente:test -m unittest scan/tests/test_scan.py vertraege/tests/test_vertraege.py tests/test_dienst.py`.

## The contract with laib's template

One container, `Network=host` (SANE finds and reaches the scanner).
`dienst.py` runs the scan's loop, the hook listener and the helper's runs;
`python3 /opt/scan.py redo <stapel>` still writes a redo order.

| Env | |
|---|---|
| `SCANNER`, `SCAN_*`, `NOTIFY_*`, `MODEL_URL`, `MODEL_LEASE`, `MODEL_KEY`, `MODEL_NAME`, `TZ` | the scan, as in laib's scan template |
| `PAPERLESS_URL` | Paperless' API from the host network, `http://127.0.0.1:8000` |
| `PAPERLESS_TOKEN` | secret, generated by the box: the API token of the narrowest Paperless user (read documents, set their tags, notes and custom fields); empty: no evaluation, said in the status |
| `PAPERLESS_USER` | that user's name (left out of the household's people) |
| `PAPERLESS_PUBLIC_URL` | Paperless' address for links in notes and messages |
| `VERTRAG_ARTEN`, `VERTRAG_VORLAUF_TAGE`, `RECHNUNG_ARTEN`, `HAUSHALT_URL`, `HAUSHALT_TOKEN`, `HAUSHALT_NAMEN` | the helper, as in laib's paperless template |
| `DOKUMENTE_LISTEN` | the hook's address, default `0.0.0.0:8720`: Paperless' pod reaches it at `host.containers.internal:8720`; laib keeps 8720 from the LAN as Haus's 8650 |
| `DOKUMENTE_WEBHOOK_TOKEN` | secret, generated by the box; Paperless' workflow sends it as `X-Dokumente-Token`; empty: no listener, hourly only |
| `AUSWERTUNG_RUHE_S` (60), `AUSWERTUNG_SPAETESTENS_S` (600), `AUSWERTUNG_STUENDLICH_S` (3600), `AUSWERTUNG_ZEIT_S` (1800) | a run once the hooks are quiet, at the latest after the first, the hourly catch-all, a run's limit |

| Mount | |
|---|---|
| `/data` (rw) | the scan's transient folder: orders, stacks, `laib-status.json` |
| `/dokumente` (rw, backed up) | the helper's record `laib-vertraege.json` (`VERTRAEGE_FILE=/dokumente/laib-vertraege.json`, the default when the folder is there): what it read, reminded and cleared, so it never asks or reminds twice |

**Paperless' side** (laib's post-deploy): the user and its token, the
workflow „Dokument hinzugefügt“ → webhook `POST
http://host.containers.internal:8720/hook` with the header. For stacks
„nur für mich“ the user also needs `add_document`; without it such a stack
is refused before a sheet is scanned, and the household's stacks go on.

**For the household or for one person** (decided 2026-10-28). The order
`start` (`laib scan start`, written by laib-haushalt) may carry
`"fuer": "haushalt" | "person"`; missing means `haushalt`, the default.
`"fuer": "person"` with `"person": "<login>"` is a stack „nur für mich“:

- Before scanning, Dokumente checks it can keep the documents private:
  Paperless answers, its user may upload, and the person has a Paperless
  account (they logged in once). If not, nothing is scanned and the person
  is told why; it never falls back to the household.
- Its documents do not go through the consume folder (that files without
  an owner, for everyone) but as uploads through the API: Paperless gives
  an upload to its uploader, so it is Dokumente's while Paperless reads it,
  seen by no one in the family. Dokumente finds each one by its checksum
  (Paperless 3 keeps the original's SHA-256, Paperless 2 its MD5; both are
  kept and asked, SHA-256 first) once filed and gives it to the person (`owner`), keeping its own view and
  change for the contracts and invoices. Until then the PDFs stay in the
  stack's archive (`/data/<zeit>/privat/`); Paperless away is waited out.
- `weiter`, `abschliessen` and `redo` never change a private stack's
  person; a redo waits until its documents are the person's.
- **Paperless' administrators see every document.** „Nur für mich“ keeps a
  document from the other family members, not from an admin. The closing
  message says so, and so must every place that offers the choice.
- Stacks from the inbox folder are the household's.

**Every filed document carries its stack** (#15): Paperless' custom field
`Stapel` (made by laib's paperless template, laib#909) is set to the stack
id (`2026-10-29T17-07-46`) on each document Dokumente files, the
household's (found by checksum once the consume folder filed it) and the
private ones (before they are given to the person). A field already naming
another stack stays (the same file filed before). Each document's Paperless
id goes into `stapel.json` and the status; one Paperless did not take within
the hour says `"paperless": "nicht angenommen"`. Haus lists a stack's
documents from Paperless by the field (`custom_field_query=["Stapel",
"exact", "<id>"]`); a split or merge in Paperless keeps it.

**One stack scans while the one before is split** (#14). The scanner is free
as soon as its feeder is empty: the stack is saved with its page list
(`stapel.json`, `phase: gescannt`) and queued; one worker splits and files
the queue in order, one stack at a time. A `start` is refused only while a
stack waits for the rest (`wartet-auf-rest`), never because another is being
split. `abschliessen`, `redo` and the inbox folder's files join the same
queue; `weiter` still belongs to the stack at the scanner. After a restart
the queue is picked up again from the stacks' `phase`, nothing is scanned
twice; a stack cut off mid-split before anything was filed is split again
from its start, one cut off mid-scan or mid-filing gets its FEHLER as before.

In the status, beside what was there:

- `zustand` stays the busiest part, so laib's Operator sees a stack in work
  whichever part has it: `scannt`, else `wartet-auf-rest`, else `trennt` or
  `legt-ab` (the worker; a queue nobody has picked up yet is `trennt` too),
  else `bereit | fertig | fehler`. `stapel`, `person`, `fuer` and the
  `seite` / `blatt` / `grund` beside it are that part's.
- `einzug`: the scanner alone, `frei | scannt | wartet-auf-rest`. Haus offers
  „Stapel scannen“ when it is `frei` (mdopp/haus follow-up).
- `trennt` (only while the worker has a stack): `{"stapel", "person", "fuer",
  "schritt": "trennt | legt-ab", "detail", "seite"?, "seiten"?}`, the page
  while it reads them.
- `warten`: the queue, `[{"stapel", "person", "fuer", "quelle", "seiten"?,
  "datei"?, "seit"}]`, first in line first.

**A doubtful split is named** (#12). Each document a split makes is a run of
pages in reading order: a page only ever extends the document of the page
right before it (the one move left: a page one found right behind its page
two goes first). A window the model answers incompletely twice is asked
again in pieces of 8 pages. A document whose pages the model never answered
for, that starts with a page two, or that runs 6 pages and more with hardly
a page that says it goes on, is named in the closing message („Bitte in
Paperless prüfen, ob richtig getrennt …“), in `plan.json` and in its line of
`letzte` as `"pruefen": "<why>"`.

**Status:** `/data/laib-status.json` as the scan wrote it (with `fuer`
beside `person`, `fuer` and `person` in each of `letzte`, whose `ende` may be `wartet`:
Paperless was away when a private stack closed; and `uebergabe`: `[{"stapel",
"person", "offen", "grund"}]`, the private stacks not yet all the person's,
with a finding, yellow after a day; each document of `letzte` with its
Paperless `id` once known; and `auftrag`: `{"aktion", "at", "angenommen",
"fuer", "person", "grund"?}`, the last order as Dokumente took it (#16): a
refused `start` or `weiter` (`angenommen: false`) leaves its German `grund`
there at once, the stack's `zustand` as it was; a taken `start` is there
with the stack's first `scannt`, before the scanner runs), plus
`auswertung`: `{"zustand": "aus | läuft | fertig | fehler", "at",
"anlass": "neue Dokumente | stündlich", "detail" (German, for the family),
"lauf": {"am", "vertraege", "rechnungen", "kontakte", "erinnerungen",
"pruefen", "fehlt"?}, "einzelheiten"? (the last log lines of a failed run),
"findings"? }`; its findings (a household correspondent left without
documents, yellow) are also in the status's top-level `findings`.
